# 開発の学び・次回チェック

## UIを変えたら、まず実画面で確認する

- 型チェックとビルド成功だけでは、表示・操作・アニメーションの正しさは確認できない。
- 変更後はローカルURLを実際に開き、少なくとも初期表示、リロード後、主な操作を確認する。
- 確認できない場合は「未確認」と明記し、確認できたように伝えない。

## 保存データは機能と同時に設計する

- Zustandの永続化に項目を足すときは、既存のlocalStorageから起動できる移行処理も同時に追加する。
- `blob:` URLのように再読み込み後に使えない値は保存しない。保存された選択状態だけが残らないよう、安全な既定値へ戻す。
- 新しいキャラクター配置プロパティには、古い保存データ向けの既定値を必ず用意する。

## 既存操作を再現するときは、参照実装を先に特定する

- 「元の操作感に合わせる」依頼では、Git履歴・ブランチ・対象リポジトリを確認してから実装する。
- 参照実装が見つからない場合は、推測で「同じ」と言わず、URL・ブランチ・スクリーンショットを求める。

## MVPの境界を明確にする

- 2D画像の左右反転・奥行き表現と、VRMの本来の3D回転は別物として扱う。
- 録画機能は、プレビュー上のDOM要素まで出力に含まれるかを実機で確認してから完成とする。
