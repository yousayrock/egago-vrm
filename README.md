# EGAGO VRM

> すべての絵には、愛(AI)がある。

EGAGO VRM は子どもたちのキャラクターと台本を使って会話を作るアプリです。

## 音声MVPとLinuxタブレット（A〜C）

声の登録と端末内生成は、VOICEVOXとは別のMOSS経路です。音声モデル本体と上流の
`ort_cpu_runtime.py` はリポジトリに含めません。MOSS経路を使う端末では公式ONNXモデルを
事前にローカルへ配置し、`EGAGO_MOSS_RUNTIME` にランタイムファイル、
`EGAGO_MOSS_MODELS` に2つのモデルフォルダを含む親フォルダを指定します。
`server/requirements-moss.txt` は追加のPython依存です。初回準備後の合成は外部通信を使いません。

```bash
git pull
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r server/requirements-moss.txt
npm ci
npm run build
export EGAGO_MOSS_RUNTIME=/path/to/MOSS-TTS-Nano/ort_cpu_runtime.py
export EGAGO_MOSS_MODELS=/path/to/local/models
EGAGO_PRODUCTION=1 python3 server/run.py
```

Linuxタブレットでは `http://127.0.0.1:8000` を開きます。開発時は別々の端末で
`python3 server/run.py` と `npm run dev:web` を動かし、`http://127.0.0.1:5173` を開きます。
`git pull` は変更がGitHubへ反映された後に実行してください。

声パネルで「この端末の声（MOSS）」を選び、1〜30秒のWAVを選ぶかマイクで録音して登録します。
声JSONを書き出して別端末で取り込むこともできます。キャラごとに声を割り当て、台本の
「音声を準備」→「台本を読む」を使います。MOSS音声の口パクは振幅方式です。
VOICEVOXのモーラ時刻に依存する自動仕草・表情・抑揚はMOSSには適用されません。
声は `server/data/voices/`、生成済みWAVは `server/data/speech/` に保存されます。
モデルが未配置の場合は登録・生成がエラーになります。MOSSを使うだけならVOICEVOXの起動は不要です。

## USBでの持ち運び

画面右側の「USB」ページからZIPを書き出し、保存ダイアログでUSBのマウント先を選びます。
取り込むときは同ページでZIPを選びます。OSの自動マウントやudev連携は使いません。
ZIPには `manifest.json`（`egago-usb-v1`、バージョン1、各ファイルのサイズとSHA-256）、
`project.json`、キャラが参照する `voices/*.json`、端末に保存された `speech/*.wav` が入ります。
取り込み時はパス・容量・形式・ハッシュを確認し、一時領域から新規パッケージとして反映します。
既存の声や音声ファイルを上書きしません。ZIP上限は256MBです。

USBパッケージにはMOSSモデル本体、VRMモデルファイル、2D画像ファイルは含みません。
移動先端末にも対応するモデルとアプリ素材を配置してください。ブラウザの保存設定も
まだ完全なプロジェクト管理ではなく、USBからの取り込みで復元します。

現段階の動画録画はThree.jsキャンバスのみで、2Dキャラを含む完成動画の保存は次段階です。
Linuxキオスク化、実機性能・本人の声の品質確認も未完了です。

- React / TypeScript / Vite
- Three.js / @pixiv/three-vrm

Tauri 版 (デスクトップアプリ化・OS レベルの透過ウィンドウ・Linux Mint 向けビルド) は次フェーズで対応します。
現在はブラウザで動作し、OBS のブラウザソースから取り込めます。

## 起動

### かんたん起動 (Windows)

`起動.bat` をダブルクリックしてください。依存の確認 → VOICEVOX の起動 → 開発サーバの起動 →
ブラウザの表示までまとめてやります。初回は `npm install` と `pip install` が走るので数分かかります。
終了するときは、開いたウィンドウで `Ctrl + C` を押してください。

スタートメニューにも「EGAGO VRM」で登録してあります
(`%APPDATA%\Microsoft\Windows\Start Menu\Programs\EGAGO VRM.lnk`)。不要なら削除してください。

`起動.bat` を編集するときの注意が 2 つあります。

- **Shift-JIS (CP932) + CRLF で保存すること。** cmd.exe はバッチをコンソールのコードページで
  読むため、UTF-8 で保存し直すと日本語行が壊れます。改行が LF だと括弧ブロックの解析もずれます
- **node / python は PATH に頼らず探しています。** エクスプローラから起動したときに PATH が
  期待どおりでないことがあるため、既定のインストール先も見に行き、見つけた場所を PATH の先頭に
  足してから `npm run dev` を呼びます (`npm run dev` の中で `python server/run.py` が
  走るので、子プロセスからも見える必要があります)

### 手動で起動する

1. **VOICEVOX を起動する** (アプリを立ち上げると、内蔵エンジンが `127.0.0.1:50021` で動きます)
2. 開発サーバを起動する

```bash
npm run dev
```

Vite (5173) と FastAPI (8000) が同時に立ち上がります。ブラウザで <http://localhost:5173> を開いてください。

VOICEVOX が起動していない場合、画面右上のインジケータが赤くなります。あとから起動すれば自動的に接続します。

## 画面

### Editor (`/`)

左がプレビュー、右が操作パネルです。

- **Speech** — 喋らせる文章。`Ctrl + Enter` でも発話します
- **Voice** — 話者 / スタイル / 話速 / 音高 / 抑揚 / 音量
- **Emotion** — 通常・喜び・怒り・悲しみ・安らぎ・驚き。ここで選んだものが**基準**になります
  (発話中に自動で変わった表情は、言い終わるとここへ戻ります)
- **Gesture** — うなずき / 首かしげ / 手を振る / 驚く / お辞儀 (手動)
- **Motion** — 呼吸・瞬き・Idle のオン/オフ
- **Auto Motion** — 表情と体の動きの自動化 (下記)
- **Model** — VRM の切り替え。プレビューに `.vrm` をドラッグしても追加できます
- **Background** — 透過 / グリーン / 単色
- **Camera** — 距離と高さ (プレビュー上のドラッグとホイールでも動かせます)

設定は自動的に保存され、次回起動時に復元されます。

**声とカメラの写りはキャラクターごとに保存されます。** 話者・スタイル・話速・音高・抑揚・音量と、
カメラの距離・高さがモデルに紐づくので、切り替えるだけでそのキャラの声と構図に戻ります
(VRM は身長も頭身もモデルごとに違うため、写りも一緒に覚えます)。
保存は自動で、まだ設定のないキャラは、そのとき使っていた設定を引き継いで登録されます。

### Stage (`/stage`)

キャラクターだけを表示する OBS 用の画面です。UI は一切ありません。
Editor で操作した内容 (発話・表情・ジェスチャー・モデル・カメラ) がそのまま反映されます。

クエリパラメータで背景を指定できます。

| URL | 背景 |
|---|---|
| `/stage?bg=alpha` | 透過 |
| `/stage?bg=green` | グリーンバック |
| `/stage` | Editor の設定に追従 |

---

## OBS への取り込み

1. ソースを追加 → **ブラウザ**
2. URL に `http://localhost:5173/stage?bg=alpha` を入力
3. 幅・高さを配信解像度に合わせる (例: 1920 × 1080)

ブラウザソースはアルファチャンネルをそのまま扱えるので、`bg=alpha` なら背景は抜けた状態で合成されます。
クロマキーで抜きたい場合は `bg=green` にして、ソースに「クロマキー」フィルタを追加してください。

> **プロパティの「表示されていないときにソースをシャットダウンする」はオフにしてください。**
> オンだとシーンを切り替えるたびに読み込み直しになります。

音声は Stage 側で再生されます。Editor と Stage の両方から同じ音が二重に鳴らないよう、
Stage が接続されている間は Editor 側を自動でミュートします (Stage パネルで切り替え可)。

## 仕組み

```
React
 |
Core
 |-- CharacterEngine   VRM の読み込みと毎フレームの更新順序
 |-- SpeechEngine      音声の再生 (AudioContext)
 |-- LipSyncEngine     口パク
 |-- MotionEngine      呼吸 / 瞬き / Idle / ジェスチャー
 |-- EmotionEngine     感情
 |-- ExpressionMixer   表情の合成
 |
VRM Adapter
 |
Three.js

FastAPI
 |- VOICEVOX Adapter
```

設計上のポイントが 3 つあります。

### 口パクは音量ではなくモーラから作る

VOICEVOX の `audio_query` が返す JSON には、モーラごとの母音と長さ (秒) が入っています。
これを使って再生前に口形のタイムラインを組み立てるため、音量エンベロープ方式より正確で、
母音に応じた正しい口の形 (`あ` `い` `う` `え` `お`) が出ます。話速を変えてもズレません。

### 表情と体の動きは 1 本のタイムラインから作る

口パク・仕草・表情・抑揚追従はすべて `speechTimeline.ts` が AudioQuery を 1 度走査して作る
同じ時間軸に乗っています。別々に計算すると口と体がわずかにずれるためです。

文の区切りも `sentenceTiming.ts` で 1 度だけ求めて仕草と表情で共有します。
別々に区切ると、仕草と表情が違う文を見てしまうためです。

**セリフの内容に合わせた仕草** — 「こんにちは」で手を振り、「ありがとう」でお辞儀します。

照合には原文ではなく、AudioQuery のモーラから組み立てた**読みのカタカナ列**を使います。
原文は漢字混じりで音声のどこに当たるか分かりませんが、モーラなら 1 文字ずつ時刻が分かるので、
その語が鳴り始める瞬間ぴったりに仕草を置けます。表記ゆれにも強く、
「こんにちは」→`コンニチワ` のように実際に発音される形で一致します。

| 語 | 仕草 |
|---|---|
| こんにちは / おはよう / またね / さようなら | 手を振る |
| ありがとう / すみません / よろしく | お辞儀 |
| びっくり / まさか / すごい | 驚く |
| なるほど / 確かに / わかりました | うなずく |
| どうして / なぜ / 不思議 | 首をかしげる |

全身を使う大きい仕草は 2 秒以上あけて出します。

> VOICEVOX は長音を「オ」で出す (`ありがとう` → `アリガトオ`) ので、
> 読みの候補もそれに合わせてあります。`src/core/autoGesture.ts` の表に追記すれば語を増やせます。

**文末に合わせた仕草** — 文章を文単位に分け、VOICEVOX が句読点の位置に入れる息継ぎ (`pause_mora`)
と対応づけて、仕草を出す時刻を先に決めます。

息継ぎは句点だけでなく**読点にも入る**ので、文と息継ぎを順番どおり 1 対 1 で当てるとずれます
(「今日は、とても嬉しい。でも…」で 2 文目が最初の読点から始まってしまう)。
文中の読点の数だけ息継ぎを読み飛ばして、文末に合わせています。

| 語尾 | 仕草 |
|---|---|
| `？` | 語尾が上がりきる少し前に首をかしげる |
| `！` | 強めにうなずく |
| `。` | 小さくうなずく |

語彙による仕草とぶつかる場合は、意味を持つ語彙側を優先します。
さらに 3 秒以上動きが無い区間には相槌を足し、強さと時刻には毎回ゆらぎを与えて、
同じ文章でも同じ動きにならないようにしています。

**セリフに合わせた表情** — 「嬉しい」で笑い、「不安」で沈みます。

仕草が「その語が鳴った瞬間」に一発だけ出るのに対して、表情は出しっぱなしになるので
**文単位**で決めます。「今日は嬉しい。でも少し不安かな。」なら前半が喜び、後半が悲しみに変わります。
照合は仕草と同じく読みのカタカナ列で行うので、`嬉しい` `うれしい` `ウレシイ` のどれでも当たります。

| 語 | 表情 |
|---|---|
| 嬉しい / 楽しい / 大好き / やった / おめでとう | 喜び |
| 悲しい / 寂しい / 不安 / 残念 / 悔しい | 悲しみ |
| むかつく / 許せない / ひどい / ふざけ | 怒り |
| びっくり / まさか / 信じられない / すごい | 驚き |
| 安心 / 落ち着く / のんびり / 大丈夫 | 安らぎ |

強さは一定ではありません。同じ感情の語が重なるほど、また「とても」「すごく」などの強調語や
`！` があるほど強く出ます。

**打ち消しは除きます。** 「嬉しくない」を喜びと取ると逆の表情になってしまうので、
語幹の直後に `ない` `なかっ` `ません` が続く場合は無視します
(「許せない」のように打ち消しを含んで初めて意味を持つ語は、表に活用ごと載せてあります)。

感情語の無い文と、言い終わったあとは、**Emotion パネルで選ばれている表情に戻ります。**
パネルの選択は「基準」で、自動表情はそれを一時的に上書きするだけ、という関係です。
`Auto Motion` の「セリフに合わせて表情が変わる」を切れば、パネルの選択だけが効くようになります。

> 語を増やすには `src/core/autoEmotion.ts` の表に追記してください。
> 活用を拾うため語幹だけを載せてあります (`ウレシ` で「嬉しい」「嬉しかった」「嬉しくて」に当たる)。

**抑揚への追従** — AudioQuery のモーラごとの `pitch` を話者に依らないよう正規化し
(話者ごとに絶対値が違うため、その発話の中での相対的な高低に直す)、声が高くなると顔が上がり、
低くなると下がります。無声モーラは直前の値を保持して、子音のたびに頭が落ちないようにしています。

**感情ごとの立ち姿** — 感情が変わると表情だけでなく姿勢と Idle の質も変わります。
悲しみならうつむいて揺れが半分になり、喜びなら胸を張って揺れが 1.35 倍に、
怒りなら小さく速い硬い動きになります。自動表情で変わったときも同じように姿勢が付いてきます。

**沈黙中の仕草** — 喋っていないあいだ、数秒おきに視線を外す・重心を移す・小さく首を傾けるなどを
ランダムに挟み、待機中の人形っぽさを消します。

### 表情はレイヤに分けて合成する

瞬き・口パク・感情がそれぞれ直接 VRM を触ると、後に書いた方が前を消してしまいます
(発話中に瞬きすると口が閉じる、など)。各エンジンは自分のレイヤに書くだけにして、
毎フレーム最後に `ExpressionMixer` が合算し、1 度だけ VRM に反映します。

### Editor と Stage は FastAPI 経由でつなぐ

OBS のブラウザソースは別プロセスの Chromium なので、`BroadcastChannel` ではユーザーのブラウザと繋がりません。
`/api/bus` の WebSocket をサーバ側で中継することで、Chrome の Editor から OBS の Stage へ確実に届きます。
発話は合成済みの音声をそのまま Stage へ送るため、二重に合成されることも音がズレることもありません。

仕草と表情だけは Stage 側でも組み立てます (発話テキストを一緒に送っています)。
そのため `Auto Motion` のオン/オフも配信します。送らないと、Editor で切ったのに
Stage のキャラだけが動き続けることになるためです。

## API

| | |
|---|---|
| `GET /api/health` | VOICEVOX の疎通状態 |
| `GET /api/speakers` | 話者とスタイルの一覧 |
| `POST /api/synthesize` | 音声合成。WAV (base64) と AudioQuery を返す |
| `GET /api/models` | `public/models/` の VRM 一覧 |
| `POST /api/models` | VRM の追加 |
| `WS /api/bus` | Editor ↔ Stage の中継 |

## VRM モデル

`public/models/` に置いた `.vrm` が Editor の一覧に出ます。
Editor から追加したファイルもここに保存されます
(Stage は別ブラウザで動くため、双方から同じ URL で読める場所に実体が必要です)。

VRM 0.x と 1.0 の両方に対応しています。

リポジトリには同梱していません (`.gitignore` で除外)。モデルの利用・配布条件は、
それぞれのモデルのライセンスに従ってください。
